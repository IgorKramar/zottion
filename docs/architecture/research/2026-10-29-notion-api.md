# Возможности Notion для zottion

Дата проверки: 29 октября 2026 года. Автор: Igor Kramar.

Исследование публичной документации; запросы в пользовательский workspace не выполнялись. Наличие endpoint не означает, что каждая операция доступна каждому тарифу, типу токена и роли. Это потребуется проверить на тестовом workspace.

## Проверенные факты

| Область | Что документировано | Следствие для клиента |
|---|---|---|
| API | В рассмотренных REST endpoints указана версия `2026-03-11` | Фиксировать `Notion-Version`, обновлять явно с проверкой совместимости. [Введение](https://developers.notion.com/reference/intro), [версионирование](https://developers.notion.com/reference/versioning) |
| Блоки | API поддерживает много типов, но возвращает `unsupported` для части содержимого, включая примеры `button` и `form` | Полное редактирование любого содержимого гарантировать нельзя. Неизвестный блок отображается как защищённый элемент. [Block](https://developers.notion.com/reference/block) |
| Markdown | Есть чтение, создание и обновление содержимого; предусмотрены `truncated`, `unknown_block_ids`, предупреждения и защита дочерних страниц | Подходит для экспорта и ограниченных правок, но не даёт основания безусловно пересоздавать всю страницу. [Руководство](https://developers.notion.com/guides/data-apis/working-with-markdown-content) |
| Базы | Database и data source — отдельные сущности; базы могут иметь несколько источников | Не отождествлять ID базы, источника данных и представления. [Модель баз](https://developers.notion.com/guides/data-apis/working-with-databases) |
| Представления | Есть создание, чтение, обновление, удаление, перечисление и запросы; описаны table, board, list, calendar, timeline, gallery, form, chart, map, dashboard | Старое утверждение «представления недоступны через API» неверно. Наличие конфигурации form не означает доступность выполнения любого form/button блока. [Работа с views](https://developers.notion.com/guides/data-apis/working-with-views), [создание](https://developers.notion.com/reference/create-view), [запрос view](https://developers.notion.com/reference/create-view-query) |
| Перенос страниц | Есть отдельный `POST /v1/pages/{page_id}/move` | Перенос страниц реализуем. Это не доказательство поддержки произвольного перемещения уже существующих обычных блоков. [Move a page](https://developers.notion.com/reference/move-page) |
| Комментарии | Документированы создание, чтение, обновление и удаление | Проверять права автора, обсуждения и операции отдельно; не обещать автоматически весь интерфейс комментариев веб-клиента. [Руководство](https://developers.notion.com/guides/data-apis/working-with-comments), [обновление](https://developers.notion.com/reference/update-a-comment), [удаление](https://developers.notion.com/reference/delete-a-comment) |
| Файлы | Есть загрузка и получение файлов; ссылки на размещённые в Notion файлы имеют срок действия | Хранить ID ресурса и срок ссылки; перед скачиванием обновлять просроченный адрес. [Загрузка](https://developers.notion.com/guides/data-apis/working-with-files-and-media), [получение](https://developers.notion.com/guides/data-apis/retrieving-files) |
| Поиск | Публичный поиск ориентирован на названия; не гарантирует полное перечисление и немедленную индексацию | Полнотекстовый поиск zottion — по локально загруженному содержимому с показом охвата. Дерево workspace не строится только из search. [Ограничения](https://developers.notion.com/reference/search-optimizations-and-limitations) |
| Лимиты | Общий бюджет зависит от тарифа; есть ограничения workspace и отдельных endpoints. Документированы 429/529, `Retry-After` и ограничения повторов записей | Нужны единый планировщик запросов, ограниченные повторы и особая обработка неоднозначного результата записи. [Request limits](https://developers.notion.com/reference/request-limits) |
| Webhooks | Нужен публичный HTTPS endpoint. Событие сообщает об изменении; актуальные данные затем читаются через API | Локальный TUI не получает webhooks напрямую на localhost. Начать с обновления активных объектов; webhook relay — отдельная последующая возможность. [Настройка](https://developers.notion.com/reference/webhooks), [доставка](https://developers.notion.com/reference/webhooks-events-delivery) |
| PAT | Персональный токен действует с правами создателя в одном workspace, зависит от политики workspace; Notion рекомендует public connection для многопользовательского продукта | PAT подходит для разработки и пользовательских скриптов; не основной способ входа массового приложения. [PAT](https://developers.notion.com/guides/get-started/personal-access-tokens) |
| Public OAuth | Документированный обмен кода и обновление токенов используют `CLIENT_SECRET` | Секрет публичного приложения нельзя помещать в распространяемый бинарник. При самостоятельном OAuth понадобится доверенный сервис обмена токенов. [Authorization](https://developers.notion.com/guides/get-started/authorization) |
| Официальный CLI | `ntn` уже выполняет API-запросы, работает со страницами и файлами | zottion должен приносить TUI, удобную предметную CLI-модель и безопасное редактирование. Дублирование raw HTTP-команд само по себе не является преимуществом. [Обзор](https://developers.notion.com/cli/get-started/overview), [API-запросы](https://developers.notion.com/cli/guides/api-requests) |
| Вход через ntn | Браузерный вход, системное хранилище, несколько workspace; гости и restricted members не могут войти. Переменная токена перекрывает keychain | Возможный быстрый публичный прототип без собственного OAuth-сервиса, но с внешней зависимостью и ограничениями аудитории. Не читать чужое хранилище токенов. [Authentication](https://developers.notion.com/cli/get-started/authentication) |
| AI | Notion Agent APIs доступны в public beta: сессии Custom Agents, поток ответов и управление агентами | Утверждение «никакого AI API нет» тоже устарело. Это не гарантия эквивалентности всем функциям Notion AI. [Agent APIs](https://developers.notion.com/guides/notion-agent-apis/overview) |

## Где доказательств пока недостаточно

В проверенном [каталоге документации](https://developers.notion.com/llms.txt) не найден полный публичный аналог веб-интерфейса для истории версий страниц, управления доступом к произвольной странице, Inbox, presence/cursors и всех настроек workspace. Это граница проведённой проверки, а не утверждение, что таких возможностей никогда не будет. Admin API для отдельных административных операций не равен интерфейсу обычного пользователя.

В рассмотренных документах обновления не найден документированный механизм условной записи с версией ресурса (`If-Match`/CAS). Поэтому предварительное чтение обнаруживает часть конфликтов, но не устраняет гонку между проверкой и записью. Не обещать строгую защиту от всех конкурентных изменений.

Произвольное перемещение/переупорядочивание существующих блоков, сохранение привязок комментариев при структурных изменениях, точные ограничения редактирования обсуждений и полное перечисление доступного содержимого остаются предметом проверочного прототипа. Не заменять перенос блоков скрытым копированием с удалением.

## Принятый стек

Rust/Ratatui/Crossterm/EdTUI, Tokio/Reqwest, Serde, bundled Rusqlite с FTS5,
Clap, keyring v1, TOML и Axum для отдельного сервиса авторизации. Связка
Ratatui 0.30 / Crossterm 0.29 / EdTUI 0.11.7 закреплена в Cargo.lock.
Выбран прямой REST; альтернативный транспорт ntn не реализуется.

## Что проверить перед реализацией редактора

1. Тестовый документ со всеми доступными типами блоков, вложенностью, упоминаниями, вложенной страницей и обсуждением.
2. Чтение → точечная правка → повторное чтение; ID и нетронутое содержимое должны сохраниться.
3. Несколько data sources в одной базе, получение реального view и его результатов, страницы свойств с дополнительной пагинацией.
4. Возможности и ограничения `ntn`: структурированные ошибки, сведения о `Retry-After`, повторы POST/PATCH, сроки, отмена, выбор workspace. Документации недостаточно, чтобы объявить его готовым транспортом надёжного редактора.
5. OAuth public connection: callback, ротация refresh token, состав доступных страниц и допустимые роли пользователей.

Проверки записей проводить только в выделенном тестовом workspace после предоставления доступа. Сейчас это план проверки, не отчёт об успешном тестировании.
