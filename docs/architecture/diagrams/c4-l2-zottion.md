# C4 L2: дополнительный self-hosted OAuth с REST API

Статус: реализованные границы; интеграционная приёмка отдельно. Дата: 29 октября 2026 года.

Эта схема показывает дополнительный режим с собственной public connection.
Основной вход через локальный `ntn` описан в [ADR-0001](../decisions/0001-use-notion-cli-for-browser-login.md) и не требует такого размещения.

Уровень контейнеров показывает запускаемые части и хранилища. TUI и CLI — режимы одного приложения, не отдельные сервисы.

```mermaid
flowchart TB
    User["Пользователь или скрипт<br/>Терминал / shell"]

    subgraph Local["Машина пользователя"]
        Client["zottion<br/>Rust · Ratatui / EdTUI · Clap<br/>Единые операции чтения и записи"]
        DB[("Локальное состояние<br/>SQLite + FTS5<br/>Снимки, черновики, журнал, поиск")]
        Secrets["Хранилище учётных данных ОС<br/>Secret Service / Keychain<br/>Access и refresh tokens"]
    end

    subgraph Hosted["Сервис публичного приложения · отдельное размещение"]
        Auth["OAuth-сервис zottion<br/>Rust · Axum · HTTPS<br/>Обмен кодов и обновление токенов"]
    end

    Notion["Notion<br/>Внешний HTTPS API<br/>Контент и OAuth token endpoint"]

    User -->|"Клавиатура или команды / stdin"| Client
    Client -->|"SQL · снимки, черновики, операции"| DB
    Client -->|"Системный API · чтение и запись токенов"| Secrets
    Client -->|"HTTPS / JSON · операции с контентом"| Notion
    Client -->|"HTTPS · вход и обновление токенов"| Auth
    Auth -->|"HTTPS / OAuth · обмен с client_secret"| Notion
```

Сервис авторизации не проксирует страницы, но видит токены при обмене и является доверенным компонентом. Нужны защита одноразовой передачи результата, сроки сеансов, исключение секретов из журналов и отдельное ревью протокола. Размещение сервиса не выполнено.
