# Проверка реализации v0.1

29 октября 2026 года. Автор: Igor Kramar.

Реализация находится в Cargo workspace `zottion` и `zottion-auth-service`.
Тегированного релиза и production-развёртывания не выполнялось.

## Локальные результаты

Проверено на Linux x86_64 с **Rust 1.91.0**, установленным в изолированный
временный каталог. Системный Rust 1.99 не использовался как доказательство
совместимости с закреплённым toolchain.

| Проверка | Результат |

| cargo fmt --all --check | Успешно |
| cargo clippy --workspace --all-targets --locked -- -D warnings | Успешно |
| cargo test --workspace --locked | 40 passed, 0 failed |
| release workspace, x86_64-unknown-linux-gnu | Успешно; собраны оба бинарника |
| PTY 80×24, Unicode paste, resize, :q, SIGINT | Успешно; termios восстановлен, черновик пережил выход |
| Архив, SHA-256, запуск из пустого каталога | Успешно на текущей системе; архив и checksum в dist |
| GitHub CI, Linux x86_64 / macOS ARM64 | fmt, Clippy, 40 тестов, PTY и release-сборки — успешно |
| GitHub packages, Linux/macOS x86_64/ARM64 | Все четыре нативные сборки и упаковка — успешно |

Набор: 11 тестов библиотеки клиента (TUI, auth, CLI), 16 прикладных,
9 ядра/SQLite/HTTP, 1 процессный CLI-сценарий, 3 OAuth-сервиса.
HTTP и OAuth provider в тестах локальные; SQLite, файловые блокировки,
очередь хранилища и клиентские операции настоящие.

Удалённые результаты: [CI, коммит 0aad66d](https://github.com/IgorKramar/zottion/actions/runs/40867241794)
и [архивы четырёх платформ, коммит 3553a7f](https://github.com/IgorKramar/zottion/actions/runs/40866833228).
Первый прогон выявил переносимость тестовых утилит: принятый сокет HTTP-мока
нужно явно переводить в блокирующий режим на macOS, а Python-скриптам — задавать
время снимка явно для старой системной SQLite Ubuntu 22.04. Исправления проверены
повторным CI; рабочая логика клиента не менялась.

Linux x86_64-архив скачан из Actions: SHA-256 совпал, запуск и PTY-проверка
прошли после распаковки. У остальных трёх архивов проверены SHA-256 и состав.

## Что подтверждено регрессиями

- Точечный PATCH сохраняет аннотации, ссылки и mentions; неизвестное защищено.
- Черновики переживают повторное открытие БД; очистка кэша сохраняет их и журнал.
  Профили и идентичности не видят чужие результаты.
- Конфликт сохраняет базовую, локальную и удалённую версии.
- Неизвестная запись автоматически не повторяется. Старое подтверждение A
  не удаляет новую правку B — при обычном ответе, сверке и обновлении TUI.
- Параллельные apply одного POST-черновика дают один POST. Чтение выполняется
  под межпроцессной блокировкой. Confirmed и условная очистка одной транзакцией;
  оставшийся старый confirmed-черновик восстанавливается без повторной отправки.
- Ошибка между ответом HTTP и локальным подтверждением даёт код 8 и сохраняет
  журнал/черновик. SQLite triggers проверяют откат confirmed/delete и всего
  пакета snapshots/FTS, без частичного локального состояния.
- Чтения ограничены сроком и числом повторов, учитывают Retry-After. Пагинация
  сохраняет results/курсор/признак усечения при сбое. Property-item чтение
  дочитывает хвост; views сохраняют query ID и общий deadline.
- URL не меняет origin после join до добавления bearer header.
- CLI принимает stdin, возвращает JSON версии 1 и нужные коды; без терминала
  TUI не стартует, без --yes удаление в скрипте не выполняется.
- EdTUI: кириллица/emoji, paste, два Esc, чистые :w/:wq, восстановление черновика,
  устаревшие ответы, поиск source и таблица/доска. Control chars исходного текста
  не удаляются скрыто при открытии редактора.
- OAuth: state/verifier, повтор callback/выдачи, TTL/лимит сеансов,
  refresh/revoke, стабильная идентичность пары и атомарные настройки 0600.

## Ревью

Проведены проверки корректности, безопасности, тестов, сопровождаемости,
производительности, API-контракта, схемы хранения и отказоустойчивости.
Все шесть подтверждённых прикладных замечаний исправлены и проверены.
Дополнительно исправлены упаковка для Python Linux runner, защита origin,
общий timeout view query и безопасное редактирование control characters.

Репозиторий изначально не имел коммитов; scope-helper не принял empty tree,
поэтому проверялся полный Git diff новой реализации без сокращённого режима.
Дополнительная внешняя проверка не дала результата из-за ошибки авторизации
инструмента; независимое заключение от неё не получено.

## До стабильного выпуска

Реальные Notion API/OAuth и native Secret Service/Keychain не проверялись:
тестового токена workspace и зарегистрированной public connection в окружении
не было. Нужна приёмка [матрицы операций](capabilities.md) в выделенном workspace,
включая сохранение ID/неизвестного, корзину/восстановление, статус и реальные views.

Нативные сборки четырёх платформ прошли на GitHub Actions; macOS ARM64 также
прошёл тесты и PTY-проверку. Нужна установка на чистых Linux/macOS.
Проверка распаковки на текущем Linux не заменяет чистую систему. Linux-архив
зависит от glibc сборочной системы, macOS-архивы не нотарифицированы.

Целевые показатели задержки на 10 тысячах страниц не измерялись. CAS с браузером
не обещается; автоматической офлайн-отправки, файлов, комментариев и смены схем нет.
Инструкции запуска/проверки сервиса: [OAuth](oauth.md).
