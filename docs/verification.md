## Реальный вход с API-токеном

Проверены создание API-token connection и доступ к выбранному корню с дочерними
страницами через обычный Chrome-профиль. `auth login --token-stdin` проверил
`/users/me` и сохранил токен в native Secret Service Linux. Новый процесс без
`NOTION_TOKEN` вернул `source: system_keyring` и `verified: true`; прошли поиск,
чтение страницы с блоками и открытие загруженной страницы в офлайн-TUI.
Установленный бинарник обновлён, корень закреплён локально. Токен не передавался
в argv и не сохранялся в открытый файл; реальные ID и содержимое не входят в fixtures.
Этот вход не проверяет OAuth. Изменяющие операции проверены отдельно ниже.

## Переработка TUI

Добавлены переносы и прокрутка блоков переменной высоты, отображение rich text,
встроенный редактор с сохранением контекста, фильтрация страниц/действий,
автоматическое открытие последней страницы или корня и явные клавиши Ctrl+S/Q.
Tab переключает панели, F2 показывает свойства. Карточки доски переносятся,
`b` переключает таблицу/доску. Современные ссылки app.notion.com принимаются
общим парсером ID для TUI и CLI.

Регрессии проверяют дочитывание длинного текста на 80×24, клик по блоку после
переносов/прокрутки, пропуск заголовков дерева, вставку ссылки в Ctrl+P,
сохранение и выход из Insert, обратное переключение флажка и защиту текстового
черновика. PTY проверяет запуск без подкоманды с закреплённым корнем,
прямой `i`, Ctrl+S/Q подряд без ожидания, Unicode, resize и восстановление termios.
CI на Linux выявил потерю Ctrl+Q во время отправки; выход теперь отложен
до успешного завершения записи, а ошибка отменяет отложенный выход. Снимки README
получены из настоящего TUI на синтетическом офлайн-кэше.

Живая проверка обнаружила смещение вставки: EdTUI 0.11.7 выполнял Vim `p` даже
в Insert. В общем обработчике редактора Insert-вставка теперь использует
`InsertChar`/`LineBreak`, а прямой `i` проходит через штатный переход режима EdTUI.
Регрессия проверяет точную позицию, кириллицу, emoji, ведущий/конечный перенос,
undo/redo и сохранение черновика. Также исправлен отказ CLI при изменении
защищённого блока: тип проверяется до сохранения черновика, поэтому отказ с
кодом 7 не оставляет неотправляемую правку. Регрессия проверяет отсутствие нового
черновика/операции и сохранность уже существующего черновика.
CI на macOS также выявил слишком тесный тайминг теста общего срока view query:
при задержке первой страницы 150 мс и лимите 250 мс иногда не приходила даже
первая страница. Интервалы увеличены до 1 и 2 секунд при общем лимите 2,5 секунды;
проверка по-прежнему отличает общий срок от нового лимита для каждой страницы.
Исправленный release-бинарник установлен локально;
повторная отправка в Notion и проверка из Chrome прошли.

Чтобы повторить проверку, подготовьте собственный Sandbox по
[матрице операций](capabilities.md#приёмка-настоящего-api). Для сравнения ответов
исключайте диагностический `request_id`: он меняется при каждом запросе и не
является содержимым блока. При проверке курсоров достаточно задать `page_size:1`
через `data-source query --file`; создавать сотни тестовых записей не требуется.

## Что подтверждено регрессиями

- Точечный PATCH сохраняет аннотации, ссылки и mentions; неизвестное защищено.
- Черновики переживают повторное открытие БД; очистка кэша сохраняет их и журнал.
  Профили и идентичности не видят чужие результаты.
- Конфликт сохраняет базовую, локальную и удалённую версии.
- Неизвестная запись автоматически не повторяется. Старое подтверждение A
  не удаляет новую правку B — при обычном ответе, сверке и обновлении TUI.
- Параллельные apply одного POST-черновика дают один POST. Чтение выполняется
  под межпроцессной блокировкой. Confirmed и условная очистка одной транзакцией;
  оставшийся старый confirmed-черновик восстанавливается без повторной отправки.
- Ошибка между ответом HTTP и локальным подтверждением даёт код 8 и сохраняет
  журнал/черновик. SQLite triggers проверяют откат confirmed/delete и всего
  пакета snapshots/FTS, без частичного локального состояния.
- Чтения ограничены сроком и числом повторов, учитывают Retry-After. Пагинация
  сохраняет results/курсор/признак усечения при сбое. Property-item чтение
  дочитывает хвост; views сохраняют query ID и общий deadline.
- URL не меняет origin после join до добавления bearer header.
- CLI принимает stdin, возвращает JSON версии 1 и нужные коды; без терминала
  TUI не стартует, без --yes удаление в скрипте не выполняется.
- EdTUI: кириллица/emoji, paste, два Esc, чистые :w/:wq, восстановление черновика,
  устаревшие ответы, поиск source и таблица/доска. Control chars исходного текста
  не удаляются скрыто при открытии редактора.
- OAuth: state/verifier, повтор callback/выдачи, TTL/лимит сеансов,
  refresh/revoke, стабильная идентичность пары и атомарные настройки 0600.

## Подготовка публичного OAuth — 30 октября

`auth login` принимает запуск без `--server`: explicit URL → runtime environment
→ сохранённый сервер выбранного profile/workspace → адрес, встроенный в сборку.
До выбора и запуска постоянного сервиса публичный адрес не задан; отсутствие
настройки даёт явную ошибку 3, неверный URL — 2 до обращения к keychain.
Срок браузерного входа по умолчанию 300 секунд, остальных команд — 30;
явный `--timeout` имеет приоритет. Новый CLI-тест сначала воспроизвёл отказ
парсера с обязательным `--server`, затем прошёл после изменения.

На Rust 1.91.0 прошли fmt, Clippy, 46 тестов, PTY и release-сборки обоих пакетов.
Проверены приоритеты серверов, HTTPS/loopback, отсутствие URL-секретов в ошибке,
чтение сохранённого сервера из TOML через отдельный CLI-процесс и разные тайм-ауты.
Новый `/health` возвращает только status и заголовок no-store. Запущенный
release-процесс с синтетическими credentials проверен по настоящему локальному
HTTP: health, start, неверные state/verifier, pending, завершение SIGINT и
отклонение старого сеанса после перезапуска. Секрет и callback code не появились
в stdout/stderr. Этот smoke не обращался к Notion и не заменяет живой OAuth.

Подготовлен [Render Blueprint](../render.yaml): один native Rust-процесс,
фиксированный toolchain, health check, ручное развёртывание и секреты вне Git.
Синтаксис YAML и необходимые поля проверены локально; сам Render пока не
создавался и конфигурация в его аккаунте не проверена. В Linux-архив включён
render.yaml; содержимое, SHA-256 и относительные ссылки из документации проверены.
Нужны выбор размещения
и согласование платного тарифа. Публичный endpoint, регистрация public connection,
браузерный login, реальный refresh/revoke и встраивание проверенного адреса
в публичные сборки остаются следующими действиями.

Клиент обновлён локально. Существующий API-token вход до и после установки
совпадает, `source: system_keyring`, `verified: true`; токены не изменялись.
Полный порядок запуска и выбор адреса: [OAuth](oauth.md).

## До стабильного выпуска

Реальный браузерный OAuth, ротация/отзыв пары и native Keychain macOS ещё
не проверены. Из [матрицы операций](capabilities.md) остаются длинные relation/people
(более 25 элементов), остальные типы свойств и реальные board views, серверное
усечение и истечение view query. Живая пагинация выше проверяет полный успешный
ответ; сбои и усечение проверены локальными регрессиями.

Нативные сборки четырёх платформ прошли на GitHub Actions; macOS ARM64 также
прошёл тесты и PTY-проверку. Нужна установка на чистых Linux/macOS.
Проверка распаковки на текущем Linux не заменяет чистую систему. Linux-архив
зависит от glibc сборочной системы, macOS-архивы не нотарифицированы.

Целевые показатели задержки на 10 тысячах страниц не измерялись. CAS с браузером
не обещается; автоматической офлайн-отправки, файлов, комментариев и смены схем нет.
Инструкции запуска/проверки сервиса: [OAuth](oauth.md).
